## 2. 未复用的部分

- **Agent 框架**：未使用 LangChain / AutoGen / LlamaIndex 等框架，工作流由 `src/agent.py` 自行实现（状态、trace、异常降级、人工复核队列），便于逐行解释。
- **大模型**：未调用任何通用大模型 API；答复文本只来自 `data/kb_faq.csv` 的原文与固定模板，避免编造政策。
- **数据集**：未使用真实学生聊天记录；`src/data_gen.py` 生成 1395 条合成工单（1200 条模板样本 + 195 条边界难例），全部可复现。
- **前端**：未使用 Vue/React 或 UI 组件库；`web/` 为原生 HTML/CSS/JS，无外部 CDN 依赖，离线可用。

## 3. 深入分析一：scikit-learn

**解决什么子任务**  
把中文工单文本转成稀疏向量，并训练一个能输出类别概率的分类器；同时提供统一的评估函数。

**输入 / 输出**  
输入：`list[str]` 文本与 `list[str]` 标签；输出：`Pipeline.predict` 的类别、`predict_proba` 的 5 维概率、`classification_report` 的 P/R/F1。

**依赖与限制**  
纯 Python + C 扩展，无外部服务；`TfidfVectorizer` 的 `tokenizer` 参数要求可序列化（本项目使用模块级 `jieba_tokenize`，保证 joblib 可加载）；`LinearSVC` 本身不输出概率，需要 `CalibratedClassifierCV` 做交叉验证校准，代价是训练时间约增加 3 倍；`ComplementNB` 概率偏极端，需在开发集上单独搜阈值。

**如何核验**  
1. 阅读官方文档确认 `char_wb` 对中文按字符边界切分、`sublinear_tf` 使用 1+log(tf)；  
2. 用同一份 train/dev 分别训练 3 个模型，记录 dev Macro-F1（0.901 / 0.887 / 0.891）；  
3. 检查 `Pipeline` 保存后重新加载，预测结果与加载前逐条一致（`joblib` 往返测试）；  
4. 在含难例测试集上复核混淆矩阵，确认错误集中在“作业↔考试”“行政↔考试”边界。

## 4. 深入分析二：Flask

**解决什么子任务**  
把本地 Agent 包装成网页可调用的服务，提供输入、结果、复核队列三类接口。

**输入 / 输出**  
`POST /api/process` 接收 `{"text": "..."}`，返回 `{"ok": true, "result": {...}}`；错误时返回 500 + `{"ok": false, "error": ...}`。

**依赖与限制**  
仅依赖 Python 标准库与 Werkzeug；开发服务器为单进程多线程，不适合公网高并发；无鉴权、无限流，只用于本地演示。

**如何核验**  
1. 用 `curl` / `Invoke-WebRequest` 请求健康检查、样例、处理、复核接口，确认状态码与 JSON 结构；  
2. 构造空文本、超长文本、非法 status，确认返回 200 + 安全提示或 400/500；  
3. 用 Chrome headless 渲染 `/?demo=1`，核对页面显示的类别、trace、JSON 与接口返回一致；  
4. 修复了初次集成时的可重入锁死锁问题（`threading.Lock` → `RLock`），并用并发请求复测。
